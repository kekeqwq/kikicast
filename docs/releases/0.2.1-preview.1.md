# Kikicast 0.2.1 Preview 1

针对用户报告的“呼出后不输入，直接 Enter 第一条，第一次无反应、第二次才执行”的小补丁。仍是 **未签名、不完整功能的预览版，不是稳定版**。

## 修复

WPF KeyboardDevice 的 IsRepeat 按上次按键/松键事件判断。Enter 执行后面板隐藏，松键可能送给恢复的外部源窗口；WPF 未收到 KeyUp 时，会把下次呼出的新 Enter 误标为重复。输入其他字符会刷新该缓存，所以只在空查询路径特别明显。

仅对 Enter 改为当前调用的按下/松开周期：呼出成功获得查询焦点后用公开 GetAsyncKeyState 做一次当前状态读取，已按住的 Enter 必须先松开；新的按下只执行一次，KeyUp 解锁。覆盖根选择、Ctrl+Enter 揭示及同窗口 Actions；不重置 WPF 私有键盘状态、不模拟任何键、不更改/重试窗口激活或强锁焦点策略。

保留 IME/composition 拒绝、长按防重复、当前行/来源/Enabled 门禁、参数命令新字段/显式 Enter，以及破坏性操作每次默认 No 确认。没有配置 schema/默认键/稳定 ID/插件协议变化。RandomWallpaper `0.1.0-preview.3` 和之前的主程序发布不改动。

## 安装

- Windows 11 x86_64：`Kikicast-0.2.1-preview.1-windows-x86_64-setup.exe`。
- Windows 11 ARM64/aarch64：`Kikicast-0.2.1-preview.1-windows-aarch64-setup.exe`。
- 当前用户 **Setup.exe**、自包含 .NET 10、开始菜单和卸载入口，沿用原产品身份/安装位置；升级前退出托盘旧实例，不强杀用户进程。
- 正常/登录启动仍只到托盘，默认双 Ctrl；登录自启默认关闭，安装/更新不执行扩展或壁纸命令。主程序卸载保留个人配置；扩展及目录 UUID/源图状态不因该补丁修改。
- 无可信签名，核对官方 SHA-256；不要关闭 Windows 安全保护，哈希不是安全签名。

## 验证范围

506测试（368 Core +138 Windows）、零警告构建。Core 覆盖新按下/重复/松开/上次丢失松键/呼出前已按住/重复呼出无副作用；命令行测试确保专用输入回归需 exact `--smoke-test` + 显式 opt-in。

自有 WPF 原生输入：先通过公开 InputManager 的 smoke-only 缺失 KeyUp seam 复现旧代码的新 Enter 被 WPF 标记 IsRepeat、选择/焦点/IME状态正确但未执行；原失败证据保留。修复后连续三次空查询各一个 Enter 执行生成的 history 入口，并检查同一 stale-repeat seam；已按住 Enter 呼出及重复不会执行，释放后的新 Enter 立即执行，恢复自有源文本/前台/native输入状态。未启动真实应用/扩展、未读写用户剪贴板或壁纸/回收源图。

打包流程对源码及两个已发布 apphost 重跑完整 default/tray/settings/window 和专用 FirstEnter 回归，随后验证私有身份相同安装配方/载荷的安装/开始菜单/同身份重装/卸载，以及启动注册精确清理/外部值保留。公开 `release-validation.json` 记录实际范围；不上传私人配置/截图。ARM64原生与 **x64-on-ARM64 仿真**分开，后者不等于原生x64签收。

受控缺失 KeyUp seam 和合成输入不替代用户的物理双 Ctrl/实际目标应用复测；真实 TSF/高对比/混合DPI/重新登录/原生x64/签名及安全性能完整验收仍待完成，稳定门禁未绕过。0.2已有功能/全部边界见 [0.2.0 Preview 1](https://github.com/kekeqwq/kikicast/releases/tag/v0.2.0-preview.1)。
