# Window layouts — placement and opt-in saved inputs

Adapted from Tinycast `docs/features/window-layouts.md`, `WindowLayout.swift`, `WindowLayoutDisplay.swift`, `WindowLayoutGeometry.swift`, `WindowLayoutPlan.swift` and `WindowLayoutRunner.swift` at `fa1c2bb2849dd826abc43b9343abad835607bdcf` (AGPL-3.0).

**Layouts edit, preview, capture, save and place eligible windows, with a default-off per-layout opt-in for missing applications and saved file/folder, URI/deeplink or literal argv inputs.** Windows-specific unsupported routes refuse explicitly; this is not complete upstream/native compatibility acceptance. Rooms is not implemented.

## Authoring and persistence

Settings → Window management → Window layouts:

- New / Edit preview / Capture open windows / Duplicate / Delete.
- Each entry chooses a current indexed application and an exact display device identity, independent width/height percentages, one of nine anchors and DIP offsets. Keep entry draft before switching; Keep layout draft stages the definition in Settings; **Save changes** registers/persists definitions and shortcut drafts atomically. Cancel/closing does not publish an unkept draft. Preview/duplicate/edit never place or launch windows.
- Enabled is independent of Show window layouts and per-item hide. Hidden/display-off definitions remain bindable; disabled layouts retain their shortcut/conflict ownership but cannot execute. Both saved window-management and application master gates are required for capture/apply. Individual application source gates are rechecked and missing/unsafe sources skipped without removing definitions/references.
- UUID `window-layout:<D-form UUID>` uses existing EntryBindings. Renaming/reordering/disable/re-enable preserves the layout identity. Duplicate regenerates the layout and all child UUIDs, mapping the optional front mark. Explicit deletion on Save removes that layout's favorite, alias, hidden flag and shortcut. Immediate customization changes are merged from current preferences before native registration and again on serialized save.
- Per-layout `LaunchMissingApplications=false` is additive schema-1. Old/absent values stay off without load rewriting. A real editor checkbox is staged by Keep layout draft then Save changes, persisted with definitions/bindings, retained across rename/copy, and never executes on edit/load/capture/save. Capture defaults off. The summary reflects the saved policy; search still does not include process/window contents.
- Additive schema-1 `WindowLayouts=[]`, `ShowWindowLayouts=true` live in channel-isolated home `settings.json`, together with their bindings; maximum64 layouts,32 entries each,512 total. Names1–120/no controls/distinct, nonempty/distinct UUIDs; application IDs must be current-type desktop/package identities, not scripts/system/window actions. Percentage fractions0–1 and finite offsets±10000 DIP; editor clamps finite numbers, malformed stored values fail validation without rewriting originals. Zero fraction requests at least1 physical pixel, not a collapsed window. Display names are labels only.
- Draft layouts join Launcher settings for shortcut/alias/favorite/hide editing. Root search has a separate Window layouts group/category (`layout`/`layouts`); name/summary/explicit keywords are cached by object identity, not external window text. Enter, Actions, global chords and Apply saved layout all resolve the **current UUID definition**, never an old row's geometry. Global visits never learn a transient query.

Apply saved layout in Settings uses default-No confirmation, closes Settings and discards unapplied drafts, then enters the same execution funnel using the saved definition/gap. Save changes first to use staged dimensions or gap. The default-No confirmation describes the **saved**, not draft, launch policy. Palette/Actions/global execution shares the saved current UUID funnel; missing apps and saved inputs open only when the saved layout explicitly opts in. Missing display/source identities always skip, regardless of that opt-in.

## Display identity and one geometry contract

`LayoutDisplays` reads public `GetDisplayConfigBufferSizes`/`QueryDisplayConfig(QDC_ONLY_ACTIVE_PATHS)` and source/target `DisplayConfigGetDeviceInfo`, joining current GDI monitor names and physical bounds from `EnumDisplayMonitors`/`GetMonitorInfoW`. It bounds128 paths/512 modes/64 monitors, native fixed structure/string buffers and at most two buffer-race read attempts. Source adapter/mode indices and coordinates must agree with the current monitor snapshot. Clone/duplicate/ambiguous paths, failed identity or mismatched bounds do not supply a layout display.

Windows persists the public **monitorDevicePath**, prefixed `monitor:`, case-insensitively compared. This is an installation/connection-specific device identity, not an invented hardware UUID or a guarantee across docking/reinstall. Runtime HMONITOR/GDI ordinals never persist. Device IDs are never passed to filesystem APIs. **Disconnected/changed identities skip their entries: no name, ordinal, nearest-display or primary-screen fallback.** Same-name connected displays are distinguished by physical bounds/coordinates in the editor, never by a guessed execution match.

`WindowLayoutGeometry.Resolve` is shared by preview and plan/execution. Canvas = target display work area, optionally inset by saved gap × destination DPI; percentages are relative to that canvas and offsets use destination DIP. Clamp and whole-edge physical rounding are shared. `Describe` is the inverse: captured layouts are gapless so current preferences cannot change captured frames. Integer contained frames round-trip across negative origins/DPI; oversized/out-of-canvas captures normalize rather than promise impossible exactness. Preview displays only identified native monitors and requested geometry; application-enforced minimum/fixed sizes are not simulated. Editor refresh and DisplaySettingsChanged use coalesced bounded reads and preserve missing authored identities; subscriptions are removed on close.

## Inventory, execution and failure

Explicit capture/apply performs a bounded gesture-scoped `EnumWindows` sweep, not polling:2048 inspected roots,256 visible PIDs,512 accepted windows,4096 indexed application descriptors for capture (apply resolves only its required IDs). Exclude Kikicast, minimized/hidden/cloaked, owned/tool/no-activate and child windows. Read only identity/start time, public process EXE or package AUMID, frame and monitor; **no window titles, contents, command lines or arbitrary file/directory scan**. Public `GetApplicationUserModelId` distinguishes registered package identities from generic hosts; unverifiable package hosts do not fall back to desktop EXEs. Desktop actual targets use ancestor-first local-file checks/long-path normalization; original `.lnk` IDs and bytes/arguments are not rewritten. Existing windows cannot be distinguished by shortcut arguments without forbidden command-line collection; same-target entries use nearest unclaimed physical frame with deterministic position/handle ties. Capture chooses a deterministic current source ID when several aliases share a process identity; it cannot infer which shortcut arguments opened a window.

Pure planning claims each handle once in authored entry order. Missing display/source produces a skip reason; unclaimed open windows skip when launch is off, or produce an immutable `LayoutOpen` when on. Actual EXE/AUMID keys deduplicate missing plain launches across shortcut aliases: at most one per actual application. Saved-input entries never claim an existing window: they request fresh opening, deduplicated by actual app plus exact input. Different inputs may request separate windows; same EXE/AUMID still cannot establish document identity. Existing plain matching windows remain nearest-unclaimed, not relaunched. Snapshot limits do not imply every desktop window was captured. Layouts deliberately have no desktop-global transactional rollback: partial placement/open outcomes are reported.

Native placement shares the serialized WindowManager gate. Before each write, revalidate stable display topology, HWND/PID/start cookie, visibility/minimized/child state; no elevation. Restore maximized state only to place that window, bounded DWM margin/readback and at most one minimum-size correction. Actual fixed/minimum dimensions reanchor **inside the requested slot**, then clamp to canvas; oversized apps pin the leading edge without fictitious resizing. An individual refusal attempts its pre-placement state restoration after another identity check; report failure honestly. A10-second batch budget and cancellation checks stop remaining placements; an already-started bounded placement finishes. Tray → Cancel running window layout is enabled only while applying. No cancellation kills a process or rolls back already-successful windows.

Layout placement never reads/writes tile/cycle/usage/Restore memory. Restore now honors a valid prior command's original state even after external/layout drift. The **next non-Restore window command** still treats observed drift as a fresh baseline, resets cycling and captures that layout frame as its new single-level Restore point. Layouts themselves create no Restore point.

At most one saved entry may be marked Bring to front. Only a successfully placed current target is eligible, after all writes, with unchanged invocation foreground and no cancellation; one `WindowActivation.Once`, no foreground-policy bypass/retry/Alt/elevation. Closure/foreground change/refusal is reported; unmarked/failed entries are not activated. Source input restoration uses the existing bounded palette close path and is not repeated over the final front target.

## Saved input authoring and Windows boundaries

Each entry's **Saved input** selector has None / local file-folder / URI / literal argv modes. Keep entry then Keep layout draft then Save changes stages/persists it with the existing UUID/binding transaction. Schema-1 `Input=null` keeps legacy behavior without rewriting. Copies deep-copy argv lists; invalid/unsupported saved input fails validation without damaging the original. File/URI values ≤4096 characters; 1–8 argv strings ≤2048 each/8192 total, preserving empty strings, spaces, quotes and operators. Argv authoring uses a JSON string array, **not command-line/shell parsing**. Ordinary text editors retain their IME behavior; only the selector disables IME interception.

- **Trusted configuration, not a sandbox:** explicit opening opt-in permits Enter/Actions/global shortcut execution without another prompt. An EXE can interpret its own argv/file/protocol as executable commands. Plaintext settings/backups contain authored values; do not store secrets. Values never enter automatic search fields/learning/diagnostics. Editing, preview, capture, copying, saving and loading do not open resources or read their contents.
- **Direct desktop EXE:** file/folder is one literal local path; URI is one literal URI; argv is the authored list via `ProcessStartInfo.ArgumentList`, no shell wrapper/templates/substitution/default-handler fallback. A selected EXE must implement its own inputs. Existing safe local paths (`~/` allowed) are rechecked at submission; no UNC/device/linked ancestry/drive root/traversal/alternate stream/wildcard. File contents are not read and directories are not scanned.
- **Original `.lnk`:** plain opening still uses the original shortcut including its arguments/working directory. Extra authored inputs on a shortcut are explicitly refused, not appended or redirected to a guessed EXE. Choose a current independently indexed direct EXE or supported registered package. This is a Windows portability limitation, not hidden shortcut mutation.
- **Registered package:** one explicit file uses public `ActivateForFile` with one `IShellItemArray` and `open` verb; one URI uses `ActivateForProtocol`. Registration/source gates and documented foreground delegation remain. A package lacking the selected contract refuses, with no association/default-browser fallback. Package folders and literal argv lists are unsupported: app-specific package command-line semantics are not emulated. Public local Shell-item/array construction and disposal are tested with an owned file; **no installed package has been activated**.
- URIs must be absolute, without authority credentials, controls, malformed Unicode or raw whitespace. File/shell/script/system-command schemes refuse. `mailto:` address syntax is not treated as authority authentication. This conservative scheme check is **not** a guarantee that an arbitrary custom protocol/app is safe; opening must be explicitly trusted.

## Missing-application and saved-input opening contract

After existing-window placement, `LayoutWindowEvents` installs public foreground/show/location WinEvents on the invoking message-loop thread **before submitting opens**; failed hooks or an incomplete initial inventory refuse all opens. Each pending entry rechecks saved UUID/Enabled/window-and-application masters, current catalogue/source gate, fresh safe `.lnk`/EXE or verified registered AUMID, exact planned match key and unchanged native display snapshot. `ApplicationLauncher` is shared with normal app Enter/global execution: ShellExecute the **original .lnk path** to preserve bytes/arguments/working directory, direct local EXE without injected arguments, or the public verified package activation primitive. A changed link target refuses instead of following stale metadata. No guessed missing paths, elevation, placeholders or launch retries.

Submission runs off the WPF dispatcher so Cancel/settings remain responsive. An already-started public OS launch call is awaited rather than detached or killed; the10-second monotonic budget bounds the gesture's opening/event wait, not an arbitrary stuck OS call or all app initialization. Public event signals coalesce in one channel slot and200ms signal-driven debounce; each launch has an immediate bounded metadata read, then **only signals** cause additional arrival reads (max64 total). Opening is sequential: bind/refuse the current request before the next, with a fresh pre-submission snapshot excluding all previously observed windows (including sibling windows). All requests share one 10-second budget; an app reusing only an old window reports no new eligible window rather than moving it. No steady-state timer, process polling, titles/contents/argv or full-drive/package scan. Hooks/deadline are disposed after this gesture.

Bind only eligible exact-key windows absent from the original/pre-next handle snapshots, once per handle, nearest authored slot; freeze HWND/PID/start cookies on first observation (max512) and never replace a reused handle's identity. The plan's original canvas/display/geometry is not recomputed during the wait. Recheck source/masters/current definition/topology before native writes; no arbitrary display fallback. A no-window timeout, source change, incomplete snapshot, launch refusal or cancellation is explicit, with launched/placed/skipped counts. **Cancel does not terminate opened apps or roll back successful placements.** New placements still do not create command Restore/tile/cycle memory. Front mark remains the existing more-conservative Windows rule: successful placement, unchanged invocation foreground, one native activation; an app's self-activation does not authorize an eligibility bypass.
